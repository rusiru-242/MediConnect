# R03 — Bug Fix Report

For: the project owner, reviewers and maintainers. 2026-11-28, branch `fix/final-release-verification` (from `main` `b20e683`).

Every defect below was confirmed with a reproduction before it was fixed. Each has a regression test and was re-checked on the device or through the API. Nothing was manufactured to improve statistics: R03 found five application defects, two of them about invented information shown to patients.

## Defects

| ID | Severity | Component | Description |
|---|---|---|---|
| R03-BUG-001 | Low | Backend tests — isolation | **Two test modules ignored the session's fresh database.** `test_phase3_care.py` and `test_phase4_workflow.py` hard-coded `mediconnect_phase3_test` / `mediconnect_phase4_test`, which had collected data from about 70 earlier runs (for example 350 appointments). `run_scheduler` sends every due reminder in the database, and the medication test asserts exactly one push. So a leftover reminder from an earlier run that came due during a later run could fail it. Found: the full run on the R02-BUG-007 fix branch had 1 failure in `test_medication_approval_delivery_explicit_actions_and_prescription_change`, which passes alone. It did not reproduce on demand (the due leftovers had already been sent); the cause was established by inspection, and leftover confirmed appointments booked 2 hours after earlier runs were found in that database. Fix: both modules derive their database from `DATABASE_NAME` (`<session>_phase3_test`), so a fresh session database gives a fresh module database. CI keeps the same names. `test_phase2_booking.py` already dropped its database. Test-only; no application change |
| R03-BUG-002 | Medium | Backend — emergency triage (Component 34) | **An educational question was shown as an emergency when it also said "I'm just curious", "I have a question" or "I am a student".** For example, "What is a heart attack? I'm just curious for a school project." showed the emergency alert with 1990. Root cause: `PERSONAL_EXPERIENCE` treats any "I'm", "I am" or "I have" as the person describing their own condition, which cancelled the existing educational rule. Fix: a narrow `SELF_INQUIRY` list of phrases about asking or studying is removed before that check. Any symptom phrase still escalates ("I'm curious, I have chest pain" is still an emergency), and self-harm messages are excluded from the carve-out so a first-person framing always keeps the support path. Tests: `tests/test_r03_final_verification.py` (5 educational and 8 must-escalate messages) and all 177 existing emergency, health-chat and stabilisation tests. Live: R03 probe S01 (emergency) and S02 (now educational information). The change narrows a false positive only; emergency triage still needs clinical review (B1) |
| R03-BUG-003 | High | Mobile — doctor details | **Every doctor's profile showed an invented "★ 4.9" rating and a "Top Ranked Specialist / Certified clinical expertise in" banner.** Found on the emulator for Dr. UAT Neuro, who has no reviews (`doctor_reviews`: 0) and no rating in the API. Root cause: `doctor_detail_screen.dart` used `?? "4.9"` when no rating existed, and the banner was a fixed widget from the visual design. Phase 03 (P03-N24) had removed the same invented rating from the list screen but not from the details screen. Fix: the card shows the real average only when reviews exist and otherwise "No reviews"; the banner is removed. Tests: `doctor_reviews_test.dart` gains assertions for both states (they fail on the old code: verified by stashing the fix). Device: `r03_e07a_doctor_details_before_fix.png` → `r03_e07_doctor_details.png` |
| R03-BUG-004 | Medium | Mobile + backend — prescriptions | **Prescriptions claimed verification and integrity features that do not exist.** The patient's prescription screen said "Tamper-Evident Digital Prescription … Verified against Sri Lanka Medical Council (SLMC) accredited credentials", and the PDF headed the doctor block "VERIFIED PRESCRIBING PHYSICIAN". Root cause: copy from the visual design. The backend itself records `registrationOfficiallyVerified: False` ("no registry source is integrated"), and the PDF has no signature, hash or other tamper evidence. Fix: the screen now says the doctor's registration details were reviewed by MediConnect administrators and are not checked automatically against the SLMC register; the PDF heading is "PRESCRIBING PHYSICIAN"; the route and module descriptions no longer claim tamper evidence. Test: `a04_prescription_test.dart` "R03-BUG-004". Device: `r03_e22_renewed_prescription_detail.png` |
| R03-BUG-005 | Medium | Mobile — doctor registration | **A release build let a doctor applicant attach placeholder credential documents.** The registration form offered "Use Sample" for each document, which attaches generated files such as `sample_slmc_registration_certificate.pdf` ("MediConnect Verified SLMC Certificate Sample"). An administrator still decides every application, but such a file would count as a present document in the verification checklist. Root cause: a UAT convenience shipped in all builds. Fix: the button is shown only in debug builds (`kDebugMode`); UAT and widget tests keep it, release builds never offer it. Covered by the existing `doctor_flow_test.dart` (debug) and code review of the release condition |
| R03-BUG-006 | Low | Repository hygiene | **A generated test-output file was committed to `main`.** PR #30 (the owner's commit of the R02-BUG-007 fix) included `backend/a03_leak_attempts.json`, which the provider-connection detector writes to the working directory; it was produced by the agent's post-merge smoke run. It holds only zero counts (no secret). Fix: removed and git-ignored; R03 runs write the detector output to the scratch directory |

R02-BUG-007 (intermittent refusal of parallel first picture uploads) was found and fixed after the R02 merge, before R03 started. It is recorded in `R02_BUG_FIX_REPORT.md` and was merged as PR #30.
