## Changed test expectations

| Test | Old expectation | New expectation | Why the change is legitimate |
|---|---|---|---|
| `test_phase05_scheduler.py::test_s06c_crash_after_claim_is_not_resent_and_is_visible` | A claimed event whose lease expired becomes `uncertain` and **0** notifications reach the patient | With push in flight (`sending`): push becomes `uncertain` and is never re-sent (`_send_fcm_push` not called); the in-app reminder is delivered **once**; monitoring shows push uncertain 1 | The old expectation encoded A02-BUG-005: a patient whose worker crashed before the in-app write never got the reminder. The safety intent (never blindly re-send an external message) is kept and still asserted |

No other existing expectation was changed. `test_phase2_booking.py` still expects `"sent"` for an accepted confirmation e-mail. That value now means "accepted by the SMTP server", which is reported under Provider accepted in monitoring.

## Observations (not defects fixed in A02)

| ID | Observation |
|---|---|
| A02-O1 | `NotificationService.check_and_send_appointment_reminders` (24 h / 1 h) is legacy code that no worker calls. The configured product rule is the care scheduler's 24 h / 2 h. It is kept because existing tests use it; it should be removed after review. |
| A02-O2 | Device-local reminders use Android inexact alarms (`inexactAllowWhileIdle`). Android may deliver them up to its window (about 1–2 minutes for near alarms, up to 1 hour for alarms a day ahead). Exact alarms need the `SCHEDULE_EXACT_ALARM` permission and a Play policy decision (owner). |
| A02-O3 | `normalize_phone` accepts only `07XXXXXXXX` and `+947XXXXXXXX`; `94…`/`0094…` forms are refused (safe, but strict). SMS templates are English only; Sinhala/Tamil SMS (UCS-2, 70 characters per segment) is not implemented. |
| A02-O4 | Two `test_phase02_booking_payment` / `test_production_security_audit` tests fail when run **alone on an empty database**, because they depend on indexes created by `ensure_indexes` at app start. They pass in the full suite and in production start-up. This is pre-existing and not caused by A02. |
| A02-O5 | The "AI" patient-communication drafting is a fixed template (appointment reminder batch) with an HMAC approval token. No LLM drafts clinical messages, which is the safe state; free-text doctor-to-patient messaging does not exist (see the remaining blockers). |
